# 原理

ChatGPT Windows 桌面端（Microsoft Store 包名 `OpenAI.Codex`）是 Electron 应用。进程启动时会读取运行时时区；Node / Electron 认 IANA 名称，例如 `America/Los_Angeles`，环境变量名是 `TZ`。

Windows 自己的时区是另一套，例如 `China Standard Time`。两者可以长期不一致：系统继续用北京时间，ChatGPT 进程只用节点时区。

## 要对齐的两件事

```text
本机 Windows 时区 ──► 给用户看时钟、文件时间，不要改
代理出口 IP     ──► ChatGPT 实际从哪个城市出网
进程环境 TZ     ──► ChatGPT / Codex 内部使用的时区
```

目标：

```text
出口 IP 所在地区的 IANA 时区  ==  ChatGPT 进程的 TZ
```

例如节点在圣何塞，就注入 `America/Los_Angeles`。不要把整台电脑改成太平洋时间。

## 社区共识：不只是时区

时区对齐只是其中一项。社区还普遍认为下面两类也会降智（同样不是官方说明）：

- **多 IP**：同一账号频繁更换出口国家/城市，或电脑、网页、手机各走不同 IP。
- **多设备同时登录**：桌面端、浏览器、手机 App 一起在线。

建议固定一个出口、一个时区、一台主力设备。本启动器不会限制多设备，需要自己避免。

## 网络

系统代理和用户级 `HTTP_PROXY` 会影响整台电脑。启动器不改这两处。

代理地址写在 `%LOCALAPPDATA%\CodexEnvAdapter\settings.json`，由界面上的「应用代理」控制：

- ChatGPT 桌面端：启动器在进程恢复前写入 `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY`，并加上 Chromium 的 `--proxy-server` 和 `--disable-quic`。开始菜单直接打开的进程拿不到这次注入。
- dots 连接这台电脑：这条连接不看上面的代理设置。勾选接管直连后，启动器只把 ChatGPT / Codex 进程树的直连 TCP 转进同一个端口，并替这些进程做 DNS。用的是随程序带上的 WinDivert（LGPL），不是系统 TUN。需要一次管理员权限，Codex 退出后自动停止。
- Codex CLI、Claude Code：勾选终端入口后，只在这两个命令自己的进程里设置同样的变量。
- Firefox：写入该配置的 `user.js`，固定走这个 HTTP 代理，并关闭 HTTP/3。不开 TUN 时，HTTP/3 和 DoH 会绕过代理直连。同时放开 Cloudflare Turnstile 的存储权限，避免 ChatGPT 网页锁定检查一直 403。改完需要重启 Firefox。

Clash 继续监听该端口。改端口时，只改启动器里的地址，不要再写全局环境变量。

## 时区为什么不能靠系统设置

改系统时区会影响所有软件、计划任务和日志。桌面端真正需要的是 **单个进程** 的 `TZ`。

注入方式（Windows 桌面端 26.924 及之后）：

1. 用 `Get-AppxPackage OpenAI.Codex` 找到当前包的完整名称和 `App` 标识
2. 通过系统的包激活接口启动 `ChatGPT.exe`，让进程带上 MSIX 包标识
3. 进程在真正跑起来之前是挂起的，这时把 `TZ` 写进它的环境块，再恢复运行
4. 若 Codex 已在运行，先退出再启动；环境变量不会热更新

直接 `CreateProcess` 虽然能带上 `TZ`，但新版本没有包标识，会在启动阶段报「该进程没有程序包标识符」并退出。开始菜单启动有包标识，却带不上 `TZ`。所以必须用本仓库的启动器。

macOS / Linux 的 `TZ` 是系统一等公民，不要再做一套 GUI，用 `scripts/unix/launch-codex.sh` 即可。说明见 [平台说明.md](平台说明.md)。

## 浏览器

网页版可以用扩展修改时区，桌面端不行。两边要分开处理，但 IANA 名称应相同。

## 不要用的做法

- 运行来路不明的 `ChatGPTTimeZoneLauncher.exe`
- 把 `TZ` 写进用户或机器级环境变量（会误伤 git、Python、Node 等）
- 为了对齐 GPT 去改 Windows 系统时区
