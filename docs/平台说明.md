# 各系统要不要做、怎么做

时区对不齐出口 IP，在 **任何会把本机时区发给模型侧的客户端** 上都可能出现。但「要不要做一个桌面程序」取决于系统怎么启动应用。

## 结论

| 环境 | 有没有这个问题 | 要不要做启动器 | 合适形态 |
|------|----------------|----------------|----------|
| **Windows 桌面端** | 有，而且最痛 | **要** | 现在的 exe。开始菜单走 AppX，带不上 `TZ` |
| **macOS 桌面端** | 有，若系统时区仍是中国、流量走美国节点 | **要，但不要做成 .app/.dmg** | 给 `ChatGPT.app` 的可执行文件直接加 `TZ=`。`open -a` 经常传不进环境变量 |
| **Linux 桌面 / Codex CLI** | 有 | **要脚本，不要 GUI** | Unix 上 `TZ` 是一等公民，一条 shell 就够 |
| **浏览器** | 有 | 不要重复造轮子 | 时区插件，IANA 名称与节点一致 |
| **iOS / Android** | 时区等于系统时区，注入不了进程环境 | **不要做 App** | 系统时区不要硬改；手机尽量别和电脑同时挂着同一账号（多设备） |
| **只在 Cursor 里用 Codex** | 部分终端会继承用户环境** | 一般不必** | 需要时在启动 Cursor 的命令前加 `TZ=`，不要写进全局 `~/.zshrc` |

Windows 才需要 exe：时区模型不是 IANA、Store 应用不能靠快捷方式传环境变量。macOS/Linux 再做一个 WinForms/Electron 壳是重复劳动，也没法在这台 Windows 机器上认真验收。

## macOS 正确启动方式

```bash
# 不要用 open -a（Launch Services 常常丢 TZ）
TZ=America/Los_Angeles "/Applications/ChatGPT.app/Contents/MacOS/ChatGPT"
```

本仓库脚本会先探测出口时区，必要时退出已运行的 ChatGPT，再按上面这种方式启动。

## Linux / Codex CLI

```bash
TZ=America/Los_Angeles codex
```

或运行 `scripts/unix/launch-codex.sh --cli`。

## 手机

不要为了对齐 GPT 去改系统时区。多设备本身就是社区里的降智诱因，手机当备用即可，不要和电脑桌面端同时在线。
